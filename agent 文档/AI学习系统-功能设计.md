# AI 学习系统：功能逻辑与 Next.js 开发规格

更新时间：2026-10-19

## 1. 产品目标

把现有 370 道 AI 题（简单 151、中等 164、困难 55）和 40 道 JS/TS、Solidity、Web3 面试题作为基础题库，共 410 道题，并持续加入经过核对的 AI 新知识。用户一次只练习一个知识模块或一个新知识专题，逐题作答，收到有依据的讲解，再通过到期复习反复练习薄弱点。

核心循环：**选主题 → 出一道题 → 用户独立作答 → 逐点评价与讲解 → 保存薄弱点 → 到期复习 → 用新问法再次验证**。

首版按单用户使用设计；如需多设备同步，再加入账号体系。整个练习流程只显示当前一道题，提交前不展示参考答案。

## 2. 内容组织

### 固定主线

基础题库按十个知识模块组织：大模型基础、Prompt 与上下文、RAG、Agent 原理、MCP/A2A 协议、Agent 框架、微调与对齐、Transformer/NLP、生产工程与安全，以及 JS/TS 与 Solidity。前九个模块沿用现有 370 道 AI 题；第十个模块加入 40 道 Web3 岗位面试题。每题保留难度、题目、核心回答、口述版、易错点和可用的官方来源，界面中的主题可跨难度汇总，但题目原始分类和来源保持可追溯。

每道题再标记一个或多个细知识点，例如“RAG / 分块”“Agent / 工具权限”。复习以知识点为单位统计薄弱情况，出题以具体题目为单位进行。

### 新知识支线

新增“新知识卡”：标题、主题、摘要、原始来源链接、来源发布日期、核对日期、适用版本、变更状态和相关题目。内容先进入候选区，经核对后才能作为练习材料。过期、被撤回或存在版本冲突的卡片停止出新题，历史作答仍保留。

建议先以官方更新记录和规范为来源，例如 [OpenAI API 更新记录](https://developers.openai.com/api/docs/changelog)、[Gemini API 更新记录](https://ai.google.dev/gemini-api/docs/changelog)、[MCP 规范更新记录](https://modelcontextprotocol.io/specification/draft/changelog) 和 [A2A 官方规范](https://a2a-protocol.org/latest/)。系统可以定期发现候选内容，但首版由人确认摘要与题目后发布。

首批可跟踪五条更新线：模型能力与 API 变化、Agent 工具与互操作协议、RAG 与多模态检索、推理及评测方法、生产安全与成本。它们是选题范围，不代表每条新闻都值得出题；只有能说明原理、工程影响或迁移决策的更新才进入练习。

## 3. 用户可见功能

| 页面 | 主要功能 |
| --- | --- |
| 今日首页 | 显示今日到期题、最近练习、薄弱模块、继续上次练习入口。 |
| 模块页 | 选择一个模块，查看题数、难度分布、已掌握比例和知识点清单。 |
| 新知识页 | 按发布日期和主题浏览新知识卡，看到来源与核对日期，进入专项练习。 |
| 练习页 | 每次只显示一道题；可输入答案、标记不确定、暂时跳过，提交后查看评价。 |
| 讲解页 | 显示命中点、遗漏点、错误点、清晰版答案、相关知识和一条追问。 |
| 错题复习页 | 按到期时间展示待复习题；支持只看“不会”“部分会”“已掌握”。 |
| 历史页 | 查看每次原始回答、当时的题目与参考版本、评分和进步曲线。 |

练习入口提供三种模式：

1. **模块练习**：选一个模块和难度，默认 5 题，逐题完成。
2. **新知识练习**：选一张已核对的新知识卡，练概念、应用和版本变化。
3. **今日复习**：优先练到期错题，题目可换一种问法，检验是否真正理解。

首版不需要复杂的社交、排行榜或多 Agent 体系。

## 4. 一次作答的完整链路

1. 用户选择模块或新知识卡，系统创建练习会话，并记录筛选条件。
2. 选题器先取该范围内已到期的薄弱题，再用未做过的题补足。默认每组 5 题；若没有到期题就全选新题。
3. 页面显示题目、难度和可选的回答框。用户可以标记“我不确定”，但提交前看不到参考答案。
4. 提交时先保存原始回答和题目版本，再发起评价。即使 AI 评价失败，作答记录也不能丢失，用户可以重试评价。
5. 评价器依据题目参考答案、评分要点和该题来源，分别指出：正确点、缺失点、事实错误、表达可改进处。对开放题接受不同但合理的技术方案。
6. 页面给出一段适合口述的示例答案，并允许用户点击“评分有误”或手动调整掌握程度。
7. 系统更新复习日期。完成一组后展示本组薄弱知识点，以及下一次建议练习的模块。

AI 评价只是学习反馈，不应把措辞与参考答案不同直接判错；涉及具体项目经历时，不代用户虚构指标或经验。评价需要保存所用模型、提示词版本和参考答案版本，方便以后复核。

## 5. 评分与复习规则

每题保留两个值：**AI 评分**和**用户自评**。AI 评分按事实准确、关键点覆盖、解释清晰、工程取舍四项给出证据；不是每道题都必须考工程取舍。系统据此映射为 0–5 分，用户可以调整最终掌握度。

| 最终分数 | 状态 | 下次复习 |
| --- | --- | --- |
| 0–2 | 不会或有关键错误 | 次日 |
| 3 | 部分会 | 3 天后 |
| 4 | 基本掌握 | 7 天后 |
| 5 | 熟练 | 21 天后 |

到期复习中若再次低于 3 分，重置连续答好次数，次日再练；连续两次达到 4 分及以上才显示“已掌握”。这是一套容易理解的首版规则，以后可根据实际遗忘情况调整间隔，不预先引入复杂算法。复习时优先给出同知识点的变式题或追问，减少死记答案。

## 6. 核心数据对象

| 对象 | 必要字段 |
| --- | --- |
| `Topic` | ID、名称、父主题、排序。 |
| `Question` | ID、题干、难度、主题/知识点、来源类型、状态、当前版本。 |
| `QuestionVersion` | 题干、参考答案、评分要点、易错点、来源及版本号。 |
| `KnowledgeSource` | URL、标题、发布日期、核对日期、适用版本、有效状态。 |
| `StudySession` | 用户、模式、选定范围、开始/结束时间、题目队列。 |
| `Attempt` | 用户、题目版本、原始回答、提交时间、评价状态、模型与评分版本。 |
| `Evaluation` | 各维评分、命中/遗漏/错误点、讲解、追问、用户反馈。 |
| `ReviewState` | 用户、题目或知识点、掌握度、连续答好次数、下次复习时间。 |

一次提交对应一条不可覆盖的 `Attempt`；反复作答新增记录。`ReviewState` 保存当前状态。这样更改题目答案或评分规则后，仍能解释历史评分。

## 7. Next.js 实现边界

使用 App Router。首页、模块列表和历史记录由服务端读取数据；作答框、计时、题目切换和即时反馈由客户端组件处理。保存练习会话、提交作答和更新掌握度用服务端函数；需要流式输出讲解时，用 Route Handler 提供流式响应。所有模型请求、密钥和评分要点留在服务端。Next.js 页面和布局默认是 Server Components，互动部分再放入 Client Components；服务端函数和 Route Handler 都要检查当前用户及其数据权限，不能仅靠页面隐藏入口。[Next.js 组件文档](https://github.com/vercel/next.js/blob/canary/docs/01-app/01-getting-started/05-server-and-client-components.mdx)、[服务端函数文档](https://github.com/vercel/next.js/blob/canary/docs/01-app/02-guides/server-actions.mdx)、[数据安全文档](https://github.com/vercel/next.js/blob/canary/docs/01-app/02-guides/data-security.mdx)。

建议路由：`/` 今日首页，`/topics` 模块列表，`/topics/[id]` 模块详情，`/knowledge` 新知识，`/practice/[sessionId]` 单题练习，`/review` 到期复习，`/history` 历史。服务端评价接口可放在 `app/api/evaluate/route.ts`；不要把大模型密钥写进前端。

首版可用关系数据库保存内容与作答记录。单机开发时先用本地数据库，准备多设备部署时再迁移到托管数据库；题库加载器从现有 Markdown 文件读取 370 道 AI 题，并合并 40 道人工维护的 Web3 面试题，同时校验题号、主题和答案数量。

## 8. MVP 顺序与验收

**第一阶段：固定题库闭环。** 导入 410 道基础题；模块选题；单题作答；参考要点讲解；保存作答；错题到期复习。先把评分规则实现为可解释的结构化评价。

**第二阶段：个性化。** 同知识点变式题、追问、自评纠错、薄弱点统计、学习进度图。

**第三阶段：新知识。** 官方来源采集、候选核对、版本更新、旧题失效与新知识专项练习。

首版验收条件：只选一个模块时不会混入其他模块；提交前看不到答案；网络或模型评价失败不丢原始回答；每次评价可追溯到题目与评分版本；低分题会在指定日期进入复习队列；“全部”基础题目数与题库 410 道一致。
