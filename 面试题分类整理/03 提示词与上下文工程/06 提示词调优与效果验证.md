## medium-11 · 有哪些设计和优化 Prompt 的技巧？请举例说明

- 难度：中等
- 原始分类：2. Prompt 与上下文工程（21 题）
- 资料类型：原始面试题
- 标签：通用、编程导航

### 核心回答

明确目标、受众、输入边界和成功标准；把参考材料用分隔符隔开，提供期望输出格式和一两个代表性示例；复杂任务先拆步骤，重要事实要求引用证据。例：“只根据下方合同片段抽取甲方、到期日，按 JSON 返回；缺失填 null，不推测。”用固定测试集比较正确率、格式率、成本和延迟，每次只改一类因素。高风险结果还需程序验证或人工审核。

### 口述练习

好的 Prompt 包含任务、上下文、约束、示例和输出契约；优化要靠测试集，而不是凭感觉改词。

### 易错点

“你是顶尖专家”不能替代信息、工具和校验。

## medium-13 · 如何设计提示词来减少 AI 的幻觉问题？

- 难度：中等
- 原始分类：2. Prompt 与上下文工程（21 题）
- 资料类型：原始面试题
- 标签：Prompt、幻觉问题

### 核心回答

把任务限定为“仅依据提供的资料回答”，要求关键结论给出处；资料不足时明确说“不知道/需补充信息”，禁止编造引用。结构化地分开事实、推断和不确定性；对金额、日期、法规等再加程序校验或人工复核。Prompt 只能降低风险，不能保证真实，根本手段还包括可信检索、工具查询和评测。

### 口述练习

给可信证据、规定无证据就拒答、要求引用，并对高风险字段做外部校验。

### 易错点

降低 temperature 不能单独解决幻觉；模型也可能编造“看似真实”的引用。

## hard-33 · 如何系统地评估和优化提示词的效果？

- 难度：困难
- 原始分类：3. RAG 与 Prompt 优化（12 题）
- 资料类型：原始面试题
- 标签：Prompt、效果评估

### 核心回答

先固定任务定义、目标用户和业务指标，建立覆盖常见、边界、攻击、缺信息和长输入的评测集；冻结模型、工具、检索和采样配置，避免混淆。指标包括正确率、格式通过率、证据忠实度、拒答率、成本与 p95 延迟。每次只改一个主要因素（任务指令、示例、上下文顺序、输出 Schema），离线成对比较并做错误归因；通过门槛后灰度上线，监控漂移与投诉。LLM-as-Judge 可辅助，但关键样本要人工校准。

### 口述练习

提示词优化是一套可复现的实验：固定基线和数据集、分维度测量、逐项改动、线上验证。

### 易错点

只挑几个成功例子看起来变好，不能证明整体性能提高。

## hard-34 · 如何处理提示词优化中的常见问题？比如输出不准确、不完整、格式错误

- 难度：困难
- 原始分类：3. RAG 与 Prompt 优化（12 题）
- 资料类型：原始面试题
- 标签：Prompt、问题诊断

### 核心回答

先分类诊断：不准确常因知识缺失、歧义或检索噪声，优先补证据、澄清和事实校验；不完整可能是输出 Token 上限、输入过长或任务要求模糊，要检查截断原因、分步生成并设完成条件；格式错误则使用明确 Schema、结构化输出 API、解析校验与有限修复重试。记录错误样本，对每类建立回归测试。不要为了纠正某一例把 Prompt 越堆越长，导致其他场景退化。

### 口述练习

不准确查证据，不完整查长度和任务边界，格式错用 Schema 与程序验证；每类问题分别回归。

### 易错点

增加“请务必正确”之类口号通常不能解决根因。

## hard-35 · 在实际项目中如何进行提示词的 A/B 测试和迭代？

- 难度：困难
- 原始分类：3. RAG 与 Prompt 优化（12 题）
- 资料类型：原始面试题
- 标签：Prompt、A/B 测试

### 核心回答

先用离线黄金集筛掉明显退化版本；线上将用户/会话稳定随机分桶，保持模型、检索、工具和流量来源尽量一致，只变更 Prompt。事先确定主指标（任务完成/人工转接等）、护栏指标（事实错误、拒答、安全、p95、成本）和最小样本量，按语言、任务、长尾分层分析。记录 Prompt 版本和实验分桶，防止会话跨版本污染；达到统计与业务显著性后再扩大流量，可随时回滚。若同时改模型与索引，应做析因实验或分别迭代。

### 口述练习

先离线评测，再稳定分桶做线上 A/B；看业务主指标和安全/成本护栏，并保证实验可回滚。

### 易错点

只看点击率或用户好评，可能掩盖事实性下降。
