## easy-64 · 如果让你从零设计一个 Agent 框架，你会优先实现哪些核心模块？为什么？

- 难度：简单
- 原始分类：4. AI Agent 原理与设计（25 题）
- 资料类型：原始面试题
- 标签：AI、大模型、Agent

### 核心回答

我会先做一个可观察、可限制、可恢复的最小执行闭环，再扩展复杂能力。

优先模块包括：统一模型适配，屏蔽基础请求差异；消息与任务状态模型，记录目标和进度；工具注册与参数校验，建立稳定输入输出；执行循环，管理工具结果及停止条件；权限与预算，限制行动范围；日志与评测，定位错误并衡量质量。

下一步加入检查点、重试与幂等，让任务遇到故障后可以恢复；再根据业务需要增加长期记忆、人工审批和子 Agent。框架应把确定性业务规则与模型决策分开，并允许任务以固定工作流运行，避免所有步骤都交给模型自由选择。

例如，先支持“查询订单并解释状态”这个小任务，通过日志确认模型选对工具、参数有效、结果引用正确，再增加物流查询和异步处理。验收应覆盖失败与取消路径，而不仅是演示一次成功。

### 口述练习

我会优先实现模型适配、状态、工具契约和循环，同时加入权限、预算及观测。先让一个真实任务稳定闭环，再做恢复、记忆与多 Agent。框架的价值是把不确定的模型行为约束成可验证的执行过程。

### 易错点

- 先堆满规划、反思和多 Agent 功能，可能掩盖基础执行不可靠的问题。
- 工具重试与状态恢复必须考虑副作用，不能直接从头重复执行。

## easy-65 · 如何设计一个生产级的 Agent 系统架构？需要考虑哪些关键模块？

- 难度：简单
- 原始分类：4. AI Agent 原理与设计（25 题）
- 资料类型：原始面试题
- 标签：AI、大模型、Agent

### 核心回答

生产架构除了模型和工具，还要覆盖接入、任务调度、状态、权限、验证和运维。入口负责身份、限流和会话隔离；编排层管理目标、上下文、循环和审批；执行层调用工具；存储层保存检查点、任务结果与记忆；观测层记录质量、成本、延迟和失败轨迹。

长任务可通过队列和工作节点异步执行，使用任务 ID 查询状态。执行节点故障后按检查点恢复；写操作使用幂等标识，防止重复消费产生重复动作。模型服务、外部工具和数据库分别设置超时、退避与熔断，失败时可以降级为人工处理或受限回答。

例如，合同审查任务先校验文件权限，队列分配执行节点，检索条款后生成报告，再核验引用是否存在；报告与证据持久化后通知用户。上线前用真实任务集评测，上线后追踪任务成功率、权限拒绝、工具失败和单任务成本。发布策略还应支持模型及提示词版本回滚。

### 口述练习

生产级 Agent 要覆盖身份接入、编排、工具执行、持久化和质量观测。我的重点是权限隔离、异步恢复、幂等和验收，再配合限流、超时及版本管理。系统是否可运维，和模型是否聪明同样重要。

### 易错点

- 保存聊天记录不等于保存了可恢复的任务执行状态。
- 成功率之外还要监控越权、重复动作、成本和高尾部延迟。

## medium-97 · 如果让你基于 OpenClaw 的设计理念从零搭建一个 Agent 框架，你会先做哪三个模块？为什么？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

第一是 Gateway/会话与路由，统一身份、入口、会话隔离和幂等；第二是 Agent Runtime，负责模型调用、工具循环、状态/预算和终止条件；第三是工具与策略层，提供 Schema、权限、沙箱和审计。先做这三块能形成最小可用且可控闭环，再逐步加 Channel 插件、Context Engine、记忆、多 Agent 和高级观测。

### 口述练习

我先做入口会话、执行循环和工具权限三模块，因为它们决定系统能否安全地运行一条完整任务。

### 易错点

不要先追求复杂多 Agent 编排，却没有会话隔离和工具权限。
