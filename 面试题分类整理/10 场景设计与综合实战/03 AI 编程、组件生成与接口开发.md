## easy-68 · 什么是 Agentic Engineering？它和 Vibe Coding 有什么区别？

- 难度：简单
- 原始分类：4. AI Agent 原理与设计（25 题）
- 资料类型：原始面试题

### 核心回答

Agentic Engineering 和 Vibe Coding 是对 AI 辅助开发实践的描述性术语，并不是定义严格、边界统一的技术标准。通常，前者更强调把 Agent 纳入工程流程，明确需求、约束、测试与审查；后者常指通过自然语言快速生成和迭代代码，开发者可能较少关注实现细节。

区别更适合从实践观察：是否理解代码及依赖，是否有可执行验收，是否审查差异，是否控制权限与成本，以及能否维护产出。两种方式可以交叉：探索原型时快速对话生成页面，随后补充测试、重构与代码审查，就进入更严谨的工程过程。

例如，让 Agent 修复支付逻辑时，应先提供失败样例和业务约束，要求只修改相关范围，执行回归测试并审查边界条件。不能只看到页面能运行就直接部署。使用 Agent 的价值是提高交付效率，同时保持对系统行为和最终质量的责任。

### 口述练习

这两个词没有统一标准。我的理解是，Agentic Engineering 更强调可验收的工程流程，Vibe Coding 更强调自然语言驱动的快速尝试。实际判断应看需求、测试、审查和维护，而不是看是否使用了某个标签。

### 易错点

- 不能仅凭代码由 AI 生成就认定开发方式属于某一类别。
- 快速生成适合探索，但成功运行一次不等于达到生产交付要求。

## medium-4 · 现场实操：给定一个包含数据Schema的API文档，请使用AI工具在15分钟内生成符合RESTful规范的CRUD接口代码，并解释关键实现逻辑

- 难度：中等
- 原始分类：1. 大模型基础、工程与场景设计（6 题）
- 资料类型：原始面试题
- 标签：大模型

### 核心回答

先把 Schema、字段约束、数据库、语言框架、鉴权和错误格式写成明确输入，让 AI 生成资源路由、DTO、校验、服务层、持久层与测试。接口通常对应 `POST /resources`、`GET /resources/{id}`、`GET /resources`、`PATCH /resources/{id}`、`DELETE /resources/{id}`；创建返回 201，资源不存在返回 404，非法输入返回 400 或 422。要求分页、唯一约束、并发更新与权限检查。运行编译、单测和一组边界请求，再解释“请求验证→业务处理→数据库事务→统一响应”的链路。

### 口述练习

我会先约束 Schema 和接口契约，再让 AI 生成分层代码，最后用编译与测试验证；关键是校验、鉴权、事务、错误码和分页。

### 易错点

不要把 AI 生成的代码当成已验证实现；也不要把 GET、DELETE 设计成有副作用或忽略幂等性。

## medium-7 · 要让AI生成一个带表单验证的Vue3组件，请写出包含以下要素的Prompt

- 难度：中等
- 原始分类：2. Prompt 与上下文工程（21 题）
- 资料类型：原始面试题
- 标签：大模型

### 核心回答

可写：“请用 Vue 3 单文件组件和 Composition API 实现用户注册表单。字段：邮箱、密码、确认密码；邮箱格式校验，密码至少 8 位，两次密码一致；失焦和提交时显示中文错误；提交期间禁用按钮，成功触发 `submit` 事件并传结构化数据。不得引入未指定依赖。请输出完整组件、类型说明和最小测试用例，兼顾键盘操作及错误提示的可访问性。”实际题目缺少“以下要素”的具体列表，面试时先确认字段和技术栈。

### 口述练习

Prompt 要交代框架版本、字段、校验规则、交互时机、输出格式、依赖约束和验收方式；缺失需求先追问。

### 易错点

只写“做一个漂亮表单”无法约束可运行性和验证行为。

## medium-8 · 假设需要让大模型生成一个React表单组件代码，请设计一个包含上下文约束的Prompt（需包含数据验证、错误提示等要求）

- 难度：中等
- 原始分类：2. Prompt 与上下文工程（21 题）
- 资料类型：原始面试题
- 标签：大模型

### 核心回答

示例：“项目使用 React + TypeScript，已有 CSS Modules，不安装新依赖。实现 `ProfileForm`，输入姓名、邮箱、年龄；姓名必填，邮箱格式合法，年龄 18–120。受控输入，失焦与提交时验证，错误显示在对应字段旁并关联 `aria-describedby`；提交成功调用 `onSubmit`，提交中禁用重复点击。输出 TSX、样式和三条测试；不得使用真实网络请求。”把上下文、禁止项和验收样例一并给出，生成后仍需运行类型检查与测试。

### 口述练习

把现有项目约束、字段规则、错误反馈、可访问性、提交契约和测试要求写进 Prompt，减少模型自由发挥。

### 易错点

不要默认模型知道项目依赖和组件接口；客户端校验也不能替代服务端校验。
