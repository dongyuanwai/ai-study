## easy-89 · 市面上有哪些主流的 LLM Agent 框架？各自的特点是什么？

- 难度：简单
- 原始分类：6. Agent 框架与应用开发（22 题）
- 资料类型：原始面试题
- 标签：大模型、AI、Agent

### 核心回答

可以按“集成、编排、技术栈”理解常见框架，而不必背一个固定排名。下面是几种有代表性的选择：

| 框架 | 主要特点 | 适合的需求 |
| --- | --- | --- |
| LangChain | 模型、工具和数据组件接口统一，提供预建 Agent | 快速集成模型和工具，搭建常见应用 |
| LangGraph | 用状态和图显式控制执行，支持持久化与人工介入 | 有分支、循环、恢复要求的长任务 |
| Spring AI | 贴合 Spring Boot，提供模型、RAG、工具和 MCP 集成 | Java 企业应用接入 AI 能力 |
| Google ADK | 提供 Agent、工作流、会话、评测与运行工具 | 多 Agent 应用和完整开发运行流程 |

这些定位分别可在 [LangChain 概览](https://docs.langchain.com/oss/python/langchain/overview)、[LangGraph 概览](https://docs.langchain.com/oss/python/langgraph/overview)、[Spring AI 概览](https://docs.spring.io/spring-ai/reference/)和 [ADK 官方文档](https://adk.dev/)核对。

选型时先看任务是否需要自主决策、是否必须恢复，以及团队语言和已有基础设施。简单抽取可能只需 SDK；复杂业务可用框架，但仍要自己实现权限、幂等、成本预算和业务评测。

### 口述练习

我会按需求选框架：LangChain 方便连接模型和工具，LangGraph 适合需要状态和恢复的复杂编排，Java 项目可以用 Spring AI，ADK 则提供 Agent 开发、运行和评测能力。决定因素是业务控制需求和团队技术栈，不是框架名气。

### 易错点

- 框架提供工程抽象，不能替代模型能力和业务系统。
- 多 Agent 并不一定更好，协调成本可能超过收益。
- LangChain 与 LangGraph 可以组合，不是必须二选一。

## medium-10 · 当大模型上下文窗口扩展到100万token时，哪些现有业务场景可能发生质变？

- 难度：中等
- 原始分类：2. Prompt 与上下文工程（21 题）
- 资料类型：原始面试题
- 标签：大模型

### 核心回答

超长窗口可能使整本手册、跨文件代码仓库、长会议/法律文档和多轮操作日志在单次调用中联合分析，减少分块与召回漏失；特别有利于跨章节引用与全局一致性检查。但可用窗口不代表模型能稳定关注每个位置，仍受成本、首字延迟、注意力退化、隐私边界和引用可核查性约束。生产系统往往仍保留检索、摘要和缓存，只是策略更灵活。

### 口述练习

百万 Token 让跨文档、跨代码文件的整体推理更可行，但不意味着 RAG 消失，成本和“中间信息遗失”仍要评测。

### 易错点

不要把标称窗口长度当作有效推理长度。

## hard-48 · 你觉得可以怎样缓解这个性能瓶颈？

- 难度：困难
- 原始分类：4. 模型原理、NLP 与部署选型（12 题）
- 资料类型：原始面试题
- 标签：Transformer

### 核心回答

题目缺少“这个瓶颈”的前文，面试时应先追问是训练显存、长序列注意力、GPU 通信，还是推理首字/解码。若指 Transformer 长序列注意力：用 FlashAttention 等 IO 感知内核、分块/稀疏/滑窗注意力，或检索/摘要缩短有效序列；若训练显存：混合精度、激活检查点、ZeRO/并行策略；若推理解码：KV Cache、分页管理、批处理、量化和并发调度。每项优化要用相同质量门槛比较吞吐、p95、显存和成本。

### 口述练习

我会先明确瓶颈指标，再按长序列、训练显存或推理解码分别选优化方案，用剖析结果而非猜测决策。

### 易错点

不应在问题缺失上下文时武断回答“加 GPU”或“用 FlashAttention”就能解决全部瓶颈。
