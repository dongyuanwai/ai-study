## medium-32 · 如何进行 RAG 调优后的效果评估？请给出真实应用场景中采用的效果评估标准与方法

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：AI、大模型、RAG

### 核心回答

以客服知识库为例，抽取真实用户问题并由业务人员标注可回答性、正确答案与证据片段，按常见/长尾/过期资料分层。检索看 Recall@K、MRR/nDCG、权限违规率；生成看事实正确率、证据忠实度、引用准确率、拒答准确率；系统看 p95 延迟、成本、人工转接率。与调优前基线做盲评和统计比较，线上小流量 A/B，监测投诉与安全事故。

### 口述练习

先建有标准证据的业务评测集，分别评估检索、回答和线上业务结果，不只看一个“准确率”。

### 易错点

不能用生成模型给自己的答案打分就当作客观真值。

## medium-35 · 在 RAG 应用的过程中，关于提示工程的设计有什么心得和技巧吗？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：AI、大模型、RAG、提示工程

### 核心回答

把检索片段标注来源、页码、时间和权限；系统指令规定仅依据片段回答、证据不足则拒答，引用要指向实际片段。上下文按相关性与多样性排序，控制长度，必要时先压缩。对模型输出设结构化字段：答案、证据、置信度或待澄清问题；关键结论做引用一致性检查。Prompt 版本与检索版本分开 A/B，便于归因。

### 口述练习

RAG Prompt 的核心是证据边界、清晰引用、无证据拒答和可检验输出，不是堆更多片段。

### 易错点

检索内容是不可信数据，不能允许其中的提示指令覆盖系统规则。

## medium-54 · RAG 系统如何标注信息来源和提供引用？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：RAG、引用标注

### 核心回答

建索引时为每块保存稳定文档 ID、标题、URL/文件路径、页码、章节、版本和权限；检索后给模型分配片段编号，要求在具体事实句旁引用编号。生成后校验编号存在、内容确实支持结论，必要时用句级证据匹配；展示时链接到原文位置。不要把模型临时编出的 URL 当引用，源文档更新时应更新或撤销旧引用。

### 口述练习

引用链路要从索引元数据贯穿到生成和前端，并校验“引用存在且真的支持答案”。

### 易错点

只在答案末尾列一堆文档名，不等于逐条事实可溯源。

## medium-56 · RAG 中如何设计 Prompt 来有效利用检索到的文档？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：RAG、Prompt 设计

### 核心回答

将片段按相关性和来源组织，标明编号、标题、时间；明确任务是“仅基于这些证据回答”，区分用户问题与检索文本，并要求缺证据时说明不能回答。必要时规定多证据冲突的处理方式和引用格式。限制片段数量，去掉重复及过期内容；对高风险结论做生成后引用核对。

### 口述练习

RAG Prompt 要让模型看清哪些是证据、哪些是不可信输入，并提供缺证据拒答和引用规则。

### 易错点

不要把检索文档里的“忽略之前指令”当作系统指令执行。

## medium-64 · 如何处理 RAG 检索不到相关文档的情况？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：RAG、检索失败处理

### 核心回答

先判断是知识库缺失、查询表述不佳、权限过滤、索引失败还是阈值过高。可做同义改写、混合检索、放宽非权限过滤或转向其他授权数据源；仍无可靠证据时明确说明无法根据知识库回答，询问澄清或转人工。记录无结果查询作为知识库补全线索。不能用模型自身常识冒充“已检索证据”。

### 口述练习

先诊断检索失败，再有限重试；真无证据就拒答或转人工，并把缺口反馈给知识库维护。

### 易错点

不要为了有答案而无限降低相似度阈值。

## medium-65 · RAG 中如何实现向量数据库的增量更新？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：RAG、增量更新

### 核心回答

为源文档建立稳定 ID、内容哈希和版本号；定期或事件驱动检测新增、修改、删除。只对变化块重新解析、切块和嵌入，按文档 ID 原子替换旧块；删除时同步清除向量和缓存。更新过程用幂等任务、失败重试和索引版本切换，避免用户同时看到新旧内容；监控索引滞后与孤儿向量。

### 口述练习

用文档 ID、哈希和版本做差量同步，更新时替换受影响块并删除旧向量。

### 易错点

只追加新向量不删除旧块，会使答案引用过期版本。

## hard-29 · 如何减少 RAG 系统的幻觉问题？有哪些实用方法？

- 难度：困难
- 原始分类：3. RAG 与 Prompt 优化（12 题）
- 资料类型：原始面试题
- 标签：RAG、幻觉问题

### 核心回答

从源头到输出分层控制：知识库保证权威、时效与版本；检索阶段做权限过滤、重排和相关性阈值；生成阶段明确仅依据证据、冲突时说明差异、无证据拒答；输出阶段做句级引用核验、结构化字段校验和高风险人工复核。建立“可回答/不可回答/冲突证据”专项集，分别测答案正确率、忠实度、拒答准确率和错误引用率。模型低温或更长 Prompt 只能辅助，不能替代证据链。

### 口述练习

减少幻觉要靠可信文档、精准检索、无证据拒答、引用核验和专项评测的组合。

### 易错点

有引用不等于引用支持结论；模型也可能编造来源编号或断章取义。

## hard-39 · 如何评估 RAG 系统的效果？检索和生成分别看哪些指标？

- 难度：困难
- 原始分类：3. RAG 与 Prompt 优化（12 题）
- 资料类型：原始面试题
- 标签：RAG、效果评估

### 核心回答

检索层需要“问题—相关证据”标注：看 Recall@K（是否找全）、Precision@K（噪声多少）、MRR/nDCG（排序质量）、覆盖率与权限违规率。生成层看答案正确率、证据忠实度、引用准确率、完整性、无证据拒答准确率和安全性；线上再看解决率、人工转接率、延迟与成本。评测集要含可回答、无答案、冲突、过期和跨租户问题；分层分析并保持数据/模型/Prompt 版本可复现。

### 口述练习

检索看“有没有找对证据”，生成看“有没有基于证据答对”，最后看真实业务收益和资源代价。

### 易错点

答案像标准答案不代表忠实于本次检索证据；引用正确性需单独核验。
