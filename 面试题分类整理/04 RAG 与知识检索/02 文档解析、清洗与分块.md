## easy-33 · 什么是 RAG 中的分块？为什么需要分块？

- 难度：简单
- 原始分类：3. RAG 检索增强生成（16 题）
- 资料类型：原始面试题
- 标签：AI、大模型、RAG

### 核心回答

分块是将长文档拆成适合索引、检索和模型阅读的小片段。一个片段可以是一段文字、一个章节、一个问答，或一张带说明的表格，最好能够表达相对完整的信息。

分块主要有三个原因：Embedding 模型有输入长度限制，长文档可能被截断；整篇文档只生成一个向量容易混合多个主题，降低细粒度检索效果；把整篇文档放进生成上下文会增加成本和噪声。检索到具体片段，能更准确地找到支持答案的证据。

块太小会丢失定义、条件和上下文，块太大又会稀释主题。一般先按标题、段落等结构切分，再设置 Token 上限；可加入适度重叠，并为每块保留文档标题、章节、页码和块位置。检索后按需补回邻近片段或父章节，兼顾查找精度与阅读完整性。

### 口述练习

分块就是把长文档拆成可独立检索的证据单元，既适应模型长度限制，也提高检索精度、减少上下文噪声。关键是保留完整语义，不能只按固定字数机械切割。块大小和重叠比例要结合资料结构、问题类型和评测结果确定。

### 易错点

- 分块不是越小越好，关键条件被切散会导致错误回答。
- 重叠会增加存储和重复召回，需要配合去重。

## easy-34 · 在 RAG 中，常见的分块策略有哪些？分别有什么区别？

- 难度：简单
- 原始分类：3. RAG 检索增强生成（16 题）
- 资料类型：原始面试题
- 标签：AI、大模型、RAG

### 核心回答

常见分块策略可以按切分依据区分：

| 策略 | 特点与适用场景 |
| --- | --- |
| 固定长度 | 按字符或 Token 切分，简单、成本低，但可能打断句子和语义。 |
| 递归切分 | 优先按段落、句子等边界切分，超长内容再细分，适合一般文本。 |
| 文档结构切分 | 按标题、章节、代码函数、问答或表格切分，结构完整，但依赖解析质量。 |
| 语义切分 | 根据句子语义变化划分主题边界，语义连贯，额外计算和调参成本较高。 |
| 父子分块 | 用小块检索，再返回对应大块，兼顾检索精度和上下文完整性。 |

重叠窗口可以与这些策略结合，用于减少边界信息丢失；它不是独立解决所有问题的办法。法规要保留条款及适用条件，代码要保留函数边界，表格要保留表头与单位。应通过代表性问题评测召回率、答案质量和成本来选策略，而不是预设统一块大小。

### 口述练习

最常见的是固定长度、递归、结构、语义和父子分块。固定长度便宜，结构切分更贴合文档，语义切分更灵活但成本高，父子分块适合需要上下文的问答。我通常先采用结构加递归切分，再依据漏召回案例调整。

### 易错点

- 字符数和 Token 数不是同一单位。
- 语义切分不一定更好，仍可能拆开表格、编号条款或跨段依赖。

## easy-35 · RAG 系统中为什么要进行文档切割？有哪些切割策略？

- 难度：简单
- 原始分类：3. RAG 检索增强生成（16 题）
- 资料类型：原始面试题
- 标签：RAG、文档切割

### 核心回答

文档切割把资料转换为粒度合适的检索单元，目的不仅是满足长度限制，还要让每个单元能够支持一个具体问题，并且能追溯到原文位置。

工程上通常先解析文档，再按内容类型选择策略：说明书按标题和段落切分；FAQ 按完整问答切分；代码按函数或类切分；表格保留表头、单位及必要的行列说明。超长单元再做递归或 Token 长度切分，必要时设置重叠。对于“小块容易命中，但回答需要更大背景”的场景，可以采用父子分块。

例如退款条款中的“七日内可退”与“定制商品除外”应一起保留，否则检索到前半句会产生错误承诺。每块应保存标题、来源、章节、版本和位置。选型时关注能否覆盖真实问题、是否保留关键条件，以及重复片段是否占满上下文。

### 口述练习

切割的目标是得到可检索、语义完整、可追溯的证据单元。我会先识别文档结构，再针对段落、FAQ、代码和表格分别处理；超长内容才按长度细分。测试时重点检查条件、例外和表头是否被切散，再调整块大小与重叠。

### 易错点

- PDF 页面通常不是天然的语义边界，条款或表格可能跨页。
- 不能在切割时丢掉来源和位置，否则后续难以引用与更新。

## medium-30 · 在 RAG 应用中为了优化检索精度，其中的数据清洗和预处理怎么做？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：AI、大模型、RAG

### 核心回答

对源文档做去重、乱码/OCR 纠错、页眉页脚和导航噪声剔除、表格结构保留、标题层级识别、版本与失效日期标记。随后按语义边界切块，给每块保存来源、页码、章节、权限和时间元数据；对扫描件抽样检查解析质量。索引前做敏感信息处理与权限映射，变更时增量更新。用“问题—标准证据”集看召回是否提升。

### 口述练习

检索效果首先取决于文档质量：去噪、结构化、合理分块、完整元数据，再用标注集验证召回。

### 易错点

不要为了清洗而删掉表格标题、单位和上下文。

## medium-34 · 在 RAG 中，索引流程中的文档解析你们怎么做的？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：AI、大模型、RAG

### 核心回答

按文件类型走不同解析器：HTML 去导航，PDF 区分可复制文本和扫描页，扫描页做 OCR，表格保留行列与表头，图片可提取图注。解析产物统一为带标题层级、页码、来源 ID、版本和权限的文档对象，再清洗、切块、嵌入、建索引。用抽样人工比对和“表格/脚注/跨页”专项集检测丢失或错序，解析失败写入死信队列供重试。

### 口述练习

解析不是简单提取纯文本；要保留文档结构、表格关系和可引用位置，并有质量检查。

### 易错点

PDF 的阅读顺序、跨栏和表格常被解析错，不能假设提取文本天然可用。

## medium-52 · RAG 的文档处理流程是怎样的？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

从数据源采集→解析 OCR/表格→清洗去重→按标题和语义切块→附来源、版本、权限元数据→生成嵌入→入库建索引；更新时识别增删改并重建受影响块。设计可追溯的文档 ID 和块 ID，保证引用、撤回与权限同步。用抽样检查和检索评测发现解析遗漏与切块不合理。

### 口述练习

文档处理不仅是切块和向量化，解析质量、元数据、版本和删除传播同样关键。

### 易错点

同一知识库混入不同版本的政策，会导致互相矛盾的回答。

## medium-66 · RAG 系统如何处理 PDF、Word、Markdown 等不同格式文档？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：RAG、文档处理

### 核心回答

按格式选择解析器：PDF 注意扫描/OCR、版面与表格；Word 读取标题、表格和批注策略；Markdown 保留标题层级、代码块和链接。解析后统一转换为 Document（文本/结构、元数据、来源位置），再清洗、切块、嵌入和索引。对不同格式建立专门质量样本，检查顺序、单位、页码及表格语义。

### 口述练习

先格式专用解析，再统一文档表示；关键是保留结构和来源，而不是简单转成一串纯文本。

### 易错点

文件解析成功不代表内容可检索，尤其扫描 PDF 和复杂表格。

## medium-68 · RAG 中文档切割的 chunk_size 和 overlap 应该如何设置？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：RAG、文档切割参数

### 核心回答

`chunk_size` 取决于文档结构、问题粒度、Embedding 最大长度和生成上下文预算；`overlap` 用于保留跨边界语义。可从自然段/标题切分起步，再设置 Token 上限；表格、代码和步骤说明尽量不拆散。用不同参数组合比较 Recall@K、答案正确率、索引体积和重复率。重叠太大会增加存储与重复证据，块太大则降低定位精度。

### 口述练习

先按语义结构切，再用 Token 上限和少量重叠兜底，最后靠真实问题评测选值。

### 易错点

不存在通用的最佳 `chunk_size=某个固定数字`。
