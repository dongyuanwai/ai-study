## easy-44 · RAG 和模型微调 Fine-tuning 有什么区别？如何选择？

- 难度：简单
- 原始分类：3. RAG 检索增强生成（16 题）
- 资料类型：原始面试题
- 标签：RAG、Fine-tuning

### 核心回答

RAG 将外部证据加入本次上下文；微调通过训练更新模型权重或适配器参数，使模型更好地执行特定任务。两者分别更擅长解决“需要哪些资料”和“如何处理任务”，并不是互斥方案。

| 维度 | RAG | 微调 |
| --- | --- | --- |
| 适合问题 | 新知识、私有资料、精确事实与溯源 | 稳定的风格、术语、格式和任务行为 |
| 更新方式 | 更新知识库与索引 | 收集训练数据并重新训练、评测 |
| 主要成本 | 检索、上下文与知识库运维 | 数据制作、训练与模型部署 |
| 主要风险 | 漏检索、错证据、噪声 | 过拟合、遗忘、记住错误模式 |

可先用提示词和基础模型建立基线：事实缺失或频繁变化时优先改进 RAG；有足够高质量样本，且模型在稳定任务上持续犯错时考虑微调。两者也能组合，例如微调模型的证据使用、拒答和输出行为，再通过 RAG 提供最新政策。必须比较业务效果、延迟和总成本。

### 口述练习

RAG 是查资料，微调是训练模型的行为。最新政策和企业知识通常优先用 RAG，稳定的任务、风格或格式可以考虑微调。二者可以组合：RAG 提供可更新的事实，微调改善模型使用事实的方式。选择应依据错误来源和评测结果。

### 易错点

- 微调不是可靠、可随时更新的知识数据库，也不能保证消除幻觉。
- RAG 也可以包含检索器训练；常见工程问答阶段则不更新生成模型权重。

## easy-111 · 什么是大模型微调？与预训练的核心区别是什么？

- 难度：简单
- 原始分类：7. 微调、对齐与模型优化（23 题）
- 资料类型：原始面试题
- 标签：大模型、AI、微调、预训练

### 核心回答

微调是在已有模型的基础上，用目标任务或领域的数据继续训练，调整全部或部分参数，让模型更符合业务需要。例如，把通用模型训练成能够按企业标注规范提取合同字段的模型。

预训练通常面对规模很大的通用语料，通过预测下一个 Token 等目标获得语言能力和基础知识；微调继承这些能力，使用更有针对性的数据学习任务、回答风格、格式或偏好。两者都包含前向计算、损失计算、反向传播和参数更新，区别主要在起点、数据分布、目标和资源规模。

微调不一定更新所有原始权重：全量微调更新整个模型，LoRA 等参数高效方法主要训练新增的小模块。实践中应先评测基础模型，再用独立验证集判断微调是否带来了可复现的业务收益。

### 口述练习

预训练让模型获得通用能力，微调让已有能力适应具体任务。比如模型已经会阅读文本，再通过合同样本学习我们的字段定义和输出规范。微调的成本通常低于从零预训练，但仍需要数据治理、训练和评测，不能把它理解成上传资料后自动建成知识库。

### 易错点

- 微调会更新训练参数，普通对话和在提示词里添加示例不会。
- 继续预训练、指令微调和偏好对齐的训练目标不同，不能混为一谈。
- 微调样本更多不保证效果更好，错误和重复数据也会被学进去。

## easy-112 · 请解释大模型微调（Fine-tuning）的原理，并说明在什么业务场景下需要微调而不是直接使用基础模型？

- 难度：简单
- 原始分类：7. 微调、对齐与模型优化（23 题）
- 资料类型：原始面试题
- 标签：大模型

### 核心回答

微调把业务样本转换为可优化的损失，利用梯度更新模型参数。以监督微调为例，给定问题和标准答案，模型逐 Token 预测答案，通过交叉熵惩罚预测错误，反复训练后提高目标回答的概率。使用 LoRA 时，反向传播主要更新适配器，基础权重保持冻结。

适合微调的情况包括：专业术语和任务定义有稳定差异；大量同类请求需要一致格式或风格；基础模型经过提示词优化后仍不能可靠完成特定分类、抽取或工具选择；希望较小模型在固定任务上达到可接受效果，从而改善延迟与成本。

例如合同审查需要稳定识别企业自定义的“高风险条款”，可以用专家标注样本微调；合同条款的最新法规依据，则仍由检索或工具提供。实施时先建立基础模型对照，检查失败原因是否确实属于模型行为，再做小规模训练和留出集评测。

### 口述练习

微调通过业务数据的损失函数更新参数，改变模型处理任务的习惯。我会在任务稳定、样本充足，而且提示词和工具方案仍无法解决质量问题时采用它。微调之前先做基线，之后同时检查任务提升、通用能力回退和部署成本，确认收益值得维护新的模型版本。

### 易错点

- 频繁变化的事实通常优先用 RAG 或接口查询维护。
- 模型本来不具备的复杂能力，未必能靠少量样本补齐。
- 先诊断失败原因，避免把检索、数据或权限问题当成微调问题。

## easy-113 · 为什么需要微调？直接用 Prompt Engineering 或 RAG 不行吗？

- 难度：简单
- 原始分类：7. 微调、对齐与模型优化（23 题）
- 资料类型：原始面试题

### 核心回答

三者改善模型的方式不同：提示词工程通过本次输入指导行为；RAG 把相关外部资料带入上下文；微调通过训练改变参数，让目标行为更容易被稳定产生。它们可以组合使用。

如果模型只是缺少最新政策，优先补知识检索；如果指令不清晰，先优化提示词；如果长期需要学习固定的标签体系、特殊写作规范或复杂领域任务，微调才更有价值。例如客服可以用 RAG 找到最新退换货规则，用提示词规定引用依据，再微调客服语气、转人工判断和回复格式。

微调也可能减少每次重复输入的大量示例，但是否降低总成本要计算数据标注、训练、评测、部署及后续更新费用。选型可按“提示词基线 → 改进检索和工具 → 小规模微调对照”的顺序，用真实测试集比较，而不是默认所有需求都需要训练。

### 口述练习

提示词解决如何表达任务，RAG 解决从哪里取得依据，微调解决模型长期如何执行任务。我会先使用成本较低的提示词和检索方案，再判断是否存在稳定的行为差距。对知识更新快、样本少的任务，微调往往不划算；对规模较大且模式稳定的任务，可以验证它的收益。

### 易错点

- RAG 与微调不是只能二选一。
- 微调不能保证准确记住并随时更新每一条业务事实。
- 更短提示词不必然使总成本更低，应比较完整生命周期成本。

## easy-114 · 常见的微调任务有哪些？

- 难度：简单
- 原始分类：7. 微调、对齐与模型优化（23 题）
- 资料类型：原始面试题
- 标签：大模型、AI、微调

### 核心回答

微调任务可以按模型需要学习的行为分类：

1. **分类与判别**：情绪分类、意图识别、风险等级判断，通常关注准确率、召回率和类别不均衡。
2. **信息抽取**：从合同、简历、票据中抽取字段，关注字段精确率、完整性和格式合规。
3. **文本生成与转换**：摘要、翻译、改写、领域问答、固定风格写作，关注事实性和任务要求满足度。
4. **指令与工具使用**：多轮对话、工具选择、参数生成、任务步骤执行，关注任务完成率和调用合法性。
5. **偏好与安全对齐**：学习更有帮助、合规的回答偏好，需要成对比较或其他反馈数据。
6. **多模态任务**：图像描述、视觉问答、文档理解，需要图文等模态间的可靠对应。

例如意图分类可以使用带标签的数据，而偏好对齐需要“同一问题下哪个回答更好”的信息。任务不同，数据结构、损失函数和评测方法也不同，不能仅用一个总训练损失描述所有效果。

### 口述练习

常见任务有分类、抽取、生成、指令遵循、工具调用和多模态理解。我的第一步是定义目标行为和成功指标，再决定标注什么数据。比如抽取任务需要字段标准答案，偏好任务需要优劣比较，数据形式应该与训练目标一致。

### 易错点

- “微调任务”描述学什么，“LoRA”描述怎样更新参数。
- 生成任务的训练损失降低，不等于业务事实准确率提高。

## easy-124 · 2026 年主流的微调工具有哪些？Unsloth、Axolotl、TRL 各有什么特点？

- 难度：简单
- 原始分类：7. 微调、对齐与模型优化（23 题）
- 资料类型：原始面试题

### 核心回答

截至 2026-10-09，三者仍是常见的开放模型微调工具，但定位不同，下面按官方文档说明能力，不按宣传数字排序。

**Unsloth** 侧重训练效率与显存优化，通过针对支持架构的内核和训练优化，提供 LoRA/QLoRA 等工作流及示例，适合快速实验和资源有限的训练。模型、GPU、量化模式的支持要逐项检查；例如某些 MoE 路径与普通稠密模型的 QLoRA 支持并不相同。[Unsloth 文档](https://unsloth.ai/docs)

**Axolotl** 侧重配置化的训练流程，用 YAML 描述模型、数据、适配器和训练参数，覆盖全量、LoRA/QLoRA、偏好训练及分布式启动等，适合团队维护可复现配置。[Axolotl 文档](https://docs.axolotl.ai)

**TRL** 是 Hugging Face 的后训练库，提供 SFT、DPO 等训练器及强化学习相关能力，可结合 Transformers、PEFT 和 Accelerate，适合用 Python 定制训练目标和流程。[TRL 文档](https://huggingface.co/docs/trl)

例如可用 TRL 组织 SFT，并搭配 Unsloth 加速；团队需要统一训练配置时可选择 Axolotl。安装时固定版本，运行小样本端到端验证，避免跨版本抄参数。

### 口述练习

Unsloth 偏效率优化，Axolotl 偏配置化训练工程，TRL 偏可编程的后训练算法。它们不是完全互斥的，我会按硬件、模型支持、定制程度和团队复现需求选择。所谓几倍加速依赖测试配置，不会直接当作我们业务的结果。

### 易错点

- 新版本支持范围变化快，要核对目标模型与已安装版本。
- 配置文件、优化后端和算法训练器处于不同抽象层。
- 框架能加载模型，不表示所有量化、分布式和对齐组合都兼容。

## medium-120 · 在进行 Fine-Tuning 时，如何选择适合的预训练模型？

- 难度：中等
- 原始分类：6. 微调与训练优化（7 题）
- 资料类型：原始面试题
- 标签：大模型、AI、微调、预训练模型

### 核心回答

先定义任务、语言、输入长度、输出形式、隐私部署和延迟/费用约束；筛选许可证、模型规模、上下文窗口、工具/多模态能力。用零样本基线和小规模试训比较候选在业务数据上的表现，再看训练稳定性、推理资源和生态支持。优先选“满足质量的最小可运维模型”，不盲目追参数量。

### 口述练习

选模型要同时看任务匹配、许可、数据语言、资源和业务评测，先做小规模基线试验。

### 易错点

不要只根据公开通用榜单决定领域微调基座。

## hard-32 · 如何结合 RAG 和 Fine-tuning 来提升提示词效果？

- 难度：困难
- 原始分类：3. RAG 与 Prompt 优化（12 题）
- 资料类型：原始面试题
- 标签：Prompt、RAG、Fine-tuning

### 核心回答

先明确两者分工：RAG 提供可更新、可引用的外部事实；微调改变模型遵循格式、领域术语、拒答和使用证据的行为。可先做 Prompt+RAG 基线，分析错误：若答案缺最新事实，补索引与检索；若证据正确但模型仍不会按格式或正确引用，可用高质量示范做 SFT/偏好优化。训练样本应包含证据、问题、正确引用和无证据拒答；测试集保持文档/时间隔离，防止模型记住答案。上线仍须引用核验与版本回归。

### 口述练习

RAG 负责“给对资料”，微调负责“学会怎么用资料”；先定位错误，再决定是否值得微调。

### 易错点

不能把 RAG 文档直接混入微调数据后期待知识实时更新；两者也不能消除提示注入。
