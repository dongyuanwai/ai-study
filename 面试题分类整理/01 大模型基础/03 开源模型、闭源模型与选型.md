## easy-5 · 开源大模型和闭源大模型各有什么优劣？2026 年主流的开源和闭源大模型有哪些？

- 难度：简单
- 原始分类：1. 大模型基础与核心概念（13 题）
- 资料类型：原始面试题

### 核心回答

严格来说，很多被称为“开源大模型”的模型只是开放了权重，其训练数据、训练代码或许可证未必完全符合传统开源定义，因此面试中最好使用“**开放权重模型**”这一更准确的说法。

| 维度 | 开放权重模型 | 闭源模型 / 托管 API |
| --- | --- | --- |
| 优点 | 可私有化部署、数据控制强、可微调和量化、可深度定制、规模化后成本可控 | 通常能力领先、上线快、免运维、工具和多模态能力完整、服务保障较成熟 |
| 缺点 | 需要 GPU、推理运维、安全治理和模型优化能力；不同许可证限制不同 | 数据需发送给服务商、供应商锁定、价格和版本受平台影响、底层不可控 |
| 适用场景 | 数据敏感、离线环境、边缘部署、垂直微调、高调用量 | 快速验证、追求前沿能力、调用量较小、团队不想维护模型基础设施 |

截至 2026-09-30，常见的主流系列可以概括为：

- **开放权重阵营**：Meta Llama、阿里 Qwen、Mistral / Ministral、DeepSeek，以及 OpenAI 的 gpt-oss 等系列。
- **闭源或以托管服务为主的阵营**：OpenAI GPT 系列、Anthropic Claude 系列、Google Gemini 系列，以及各云厂商提供的商业模型服务。

模型选型不能只比较公开榜单，应使用企业自己的数据集测试准确率、幻觉率、延迟、并发、单位成本、许可证、数据合规和运维复杂度。常见的落地方式是“闭源强模型做复杂任务，开放权重小模型承担高频或敏感任务”的混合架构。

### 口述练习

开放权重模型的优势是可控、可私有化、可深度微调，代价是要承担 GPU、部署和安全运维；闭源模型通常能力更强、接入更快，但存在数据治理、成本和供应商锁定问题。2026 年常见开放权重系列有 Llama、Qwen、Mistral、DeepSeek 和 gpt-oss，闭源主流有 GPT、Claude、Gemini。最终应基于真实业务评测，而不是只看参数量或榜单。

### 易错点

- 可下载权重”不代表可以无条件商用，必须检查许可证。
- 开放权重部署并不天然更便宜，小规模调用时托管 API 可能更划算。
- 模型迭代很快，面试时宜说“系列 + 截止日期”，不要死背版本号。

## easy-13 · LLaMA 有哪些实际应用？

- 难度：简单
- 原始分类：1. 大模型基础与核心概念（13 题）
- 资料类型：原始面试题
- 标签：自然语言处理（NLP）、大语言模型

### 核心回答

LLaMA 是 Meta 发布的大模型系列，开放权重和丰富生态使它经常被用于私有部署、研究和领域定制。常见应用包括：

1. **企业知识助手**：结合 RAG 回答内部制度、产品、合同和技术文档问题。
2. **文本处理**：摘要、分类、情感分析、信息抽取、改写和翻译。
3. **代码助手**：代码生成、解释、测试生成、错误定位和代码审查。
4. **领域模型**：通过 SFT、LoRA 等方式适配客服、法律、金融、医疗或工业语料。
5. **Agent 系统**：负责规划、工具选择和结果总结，连接搜索、数据库和业务 API。
6. **本地与边缘部署**：量化后运行在企业服务器、工作站，部分小型版本还可用于端侧场景。
7. **合成数据与教师模型**：生成指令数据、分类样本或辅助训练更小的模型。
8. **多模态应用**：使用支持视觉等模态的版本处理图片理解和文档问答。

选择 LLaMA 的主要原因通常是部署控制、数据隐私、可定制性和社区工具完善。但落地前仍需评估许可证、模型版本、硬件成本、中文和领域效果、安全对齐及运维能力。开放权重并不意味着可以不做访问控制和内容安全。

### 口述练习

LLaMA 常用于企业私有知识库、文本抽取和分类、代码助手、领域微调、Agent 以及本地或边缘部署。它的优势是开放权重、生态成熟、可量化和可微调，但真正落地还要评估许可证、硬件成本、中文及领域效果，并补齐安全治理和持续评测。

### 易错点

- LLaMA 是一个持续演进的模型系列，不同版本和尺寸能力差异很大。
- 私有部署可以加强数据控制，但不会自动解决幻觉、安全和合规问题。
- 使用前必须核对具体版本许可证，而不能笼统认为“开源即可任意商用”。

---

### 本分类速记

1. Token 是计算与计费单位；输入、输出及缓存 Token 可能分别计价。
2. 参数量影响容量，但数据、架构、训练方法和业务适配同样重要。
3. 训练更新参数，推理固定参数；训练重算力和显存，推理重延迟、吞吐及成本。
4. 上下文窗口是临时工作区，不是知识库，也不是长期记忆。
5. 开放权重强调控制和定制，闭源 API 强调前沿能力和使用便利。
6. 蒸馏迁移能力，量化降低精度；两者可以组合。
7. 涌现能力需要实测，不能由参数量直接推断。
8. 幻觉无法靠单一技巧消除，需要检索、工具、校验、评测和人工审核协同治理。
9. 深度思考增加推理预算，自适应思考按任务难度动态分配预算。
10. 结构化输出保证机器可解析；Schema 正确不代表语义正确。
11. GPT Structured Outputs 比 JSON Mode 多了 Schema 遵循保证。
12. 公共 Benchmark 用于初筛，私有业务评测决定最终选型。
13. LLaMA 适合私有部署和深度定制，但仍需处理许可证、硬件和安全问题。
