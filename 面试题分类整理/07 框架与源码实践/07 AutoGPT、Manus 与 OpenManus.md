## easy-107 · 什么是 Manus？说说你对它的了解

- 难度：简单
- 原始分类：6. Agent 框架与应用开发（22 题）
- 资料类型：原始面试题
- 标签：AI、大模型、Manus

### 核心回答

Manus 是面向完成任务和交付结果的通用 AI Agent 产品。官方资料将其描述为能够规划、执行任务，并在带网络和文件系统的沙箱计算环境中工作；产品展示包含研究、网站、幻灯片等交付形式。[Manus 官方介绍](https://manus.im/docs/introduction/welcome)、[Manus 产品页面](https://manus.im/)

可以从使用方式理解它：用户提出目标及约束，系统组织多步操作并产生文件或其他成果，用户再检查成果是否符合要求。这种交付方式需要模型、工具和运行环境共同参与，其评价重点除了回答质量，还有任务成功率、工具错误和结果可验证性。

但从产品展示不能准确推导底层实现。是否采用特定多 Agent 架构、具体模型、调度算法或内部记忆机制，要以公开技术材料为依据；不能把其他开源项目的结构直接当作 Manus 的实现。

在实际选择中，关注它能否访问所需系统、输出是否可复核、数据处理规则与成本限制。涉及重要提交或发布，仍要检查实际结果，不能把任务状态提示当成业务成功凭证。

### 口述练习

Manus 是以任务执行和结果交付为目标的通用 Agent 产品，通过沙箱计算环境开展多步工作。它展示了 Agent 从问答走向行动的产品形态。对未公开的内部模型和编排细节，我不会仅凭演示推断。

### 易错点

- Manus 产品、开源复现项目和基础模型是不同概念。
- 有自主执行能力不等于每次任务都可靠完成。
- 公共产品资料没有披露的实现细节，应明确不确定。

## hard-15 · AutoGPT 如何实现自主决策？

- 难度：困难
- 原始分类：2. Agent、推理与框架（16 题）
- 资料类型：原始面试题
- 标签：大模型、AI、Agent、LangChain、AutoGPT

### 核心回答

要区分经典 Auto-GPT Agent 与后来扩展的平台。经典实现接收目标和当前记忆，模型提出下一步行动/工具调用，系统解析并展示建议，按配置征求用户确认或自动执行，再把工具观察结果写回上下文，循环直到完成、失败或达到步数上限。自主性来自“模型提议 + 工具反馈”的闭环，不是模型直接拥有操作系统权限。生产化还需预算、权限、终止条件、幂等和审批；不同版本的组件和默认行为可能不同。

### 口述练习

AutoGPT 用“提出动作→执行工具→观察反馈→继续规划”的循环自主推进目标，但执行权仍由宿主程序控制。

### 易错点

不能把“连续模式”理解为无限安全；循环和副作用必须设硬边界。

## hard-17 · 什么是 OpenManus？它的实现原理是什么？

- 难度：困难
- 原始分类：2. Agent、推理与框架（16 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

OpenManus 是开源通用 Agent 项目，使用 LLM 与浏览器、Python 执行等工具来完成多步任务。可概括为任务进入 Agent→模型根据工具描述规划/调用→工具执行并返回观察→Agent 更新状态、继续或终止；项目还提供规划式多 Agent 流程。它是具体实现而非一种新的基础模型。面试应说明所讨论的版本和实际源码模块，不能把演示中的“沙箱”直接当成企业级隔离保证。

### 口述练习

OpenManus 通过模型推理、工具调用和循环反馈实现通用任务执行，核心能力来自浏览器/代码等外部工具。

### 易错点

不要将 OpenManus 与商业产品 Manus 等同，也不要声称它天然具备生产级权限治理。
