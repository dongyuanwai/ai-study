## easy-103 · 什么是 Spring AI 框架？它有哪些核心特性？

- 难度：简单
- 原始分类：6. Agent 框架与应用开发（22 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

Spring AI 是 Spring 生态的大模型应用框架，帮助 Java 应用连接模型服务、企业数据和业务 API。它沿用 Spring Boot 的依赖注入、配置和自动装配方式，适合把 AI 能力融入已有后端系统。[Spring AI 官方介绍](https://docs.spring.io/spring-ai/reference/)

核心能力包括模型接口和 `ChatClient`，用于组织提示词、调用及流式响应；Embedding 与 VectorStore 抽象，用于向量检索；工具调用，用于连接业务函数；结构化结果转换；以及用于会话和 RAG 等处理的 Advisors。框架还提供 MCP 集成和可观测能力，实际支持情况取决于选用版本及集成包。

`ChatClient` 是面向应用的调用入口，Advisor 在调用链中增强请求或处理响应。例如检索 Advisor 加入相关知识，会话 Advisor 加入历史，从而减少控制器中的重复逻辑。[ChatClient 文档](https://docs.spring.io/spring-ai/reference/api/chatclient.html)、[Advisors 文档](https://docs.spring.io/spring-ai/reference/api/advisors.html)

它不负责自动训练模型，也不自动解决鉴权和幻觉。项目应使用匹配的 BOM、Starter 和 Spring Boot 版本，并独立维护业务安全及评测。

### 口述练习

Spring AI 是面向 Java 和 Spring Boot 的大模型应用框架，提供模型调用、ChatClient、向量检索、工具、结构化输出和 Advisor 等能力。它让 AI 接入符合已有 Spring 工程习惯，但业务权限和效果保证仍要自己设计。

### 易错点

- Spring AI 不等于一个大模型训练框架。
- 抽象统一不代表所有模型支持相同功能。
- 需要按实际依赖版本核对 Starter 和 API。

## easy-104 · 你在 AI 超级智能体项目中如何利用 Spring AI 开发应用？用到了哪些特性？

- 难度：简单
- 原始分类：6. Agent 框架与应用开发（22 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

这是一道项目经历题。下面提供示例回答结构，需按真实经历删改；未实现的能力应表述为设计方案，不能当作已完成项目经历。

示例：我会将智能体拆成模型调用、知识检索、业务工具和运行控制四部分。使用 `ChatClient` 统一请求及流式响应；通过会话 Advisor 管理历史，通过检索 Advisor 获取知识库证据；将查询业务数据封装为受权限控制的工具；用结构化结果转换向前端返回可校验字段。这些组合能力有官方示例可核对。[Spring AI Advisors](https://docs.spring.io/spring-ai/reference/api/advisors.html)

复杂任务的执行顺序、停止条件和重试策略由应用层明确控制，不能只依靠一段 Prompt。写操作先做鉴权与确认，工具结果限制大小，并用追踪关联模型、检索和执行步骤。

面试时重点说明一条实际链路、一个真实问题以及验证方法。例如检索召回不足时如何改数据和评测，工具超时如何降级。效果数字只使用可复现记录；如果没有数据，可以描述指标和测试方法。

### 口述练习

如果实际项目用过，我会说明 ChatClient 如何调用模型、Advisor 如何管理会话与 RAG、工具如何连接业务，再解释超时、权限和终止条件。最后用真实测试结果证明效果；没有实施过的部分会明确说是设计方案。

### 易错点

- 本题不能照抄成不存在的个人项目经历。
- 流式输出改善体验，不代表任务已经执行成功。
- “框架支持”与“项目实际使用”必须分开。

## easy-105 · 如何实现程序和 AI 大模型的集成？有哪些方式？

- 难度：简单
- 原始分类：6. Agent 框架与应用开发（22 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

常见方式有四种：直接调用模型服务 HTTP API；使用供应商 SDK；通过应用框架统一接入；或者把开放权重模型部署为服务后调用。集成方式决定接口和运维分工，模型是否云端或本地则是部署选择，两者可以组合。

直接 API 或 SDK 适合调用链短、需要完整控制请求的场景；框架适合同时接入模型、RAG、会话和工具；本地部署适合特定数据或离线要求，但需要承担硬件、推理服务和模型维护成本。Spring AI 的 `ChatClient` 就是框架接入的一种入口。[Spring AI ChatClient](https://docs.spring.io/spring-ai/reference/api/chatclient.html)

典型调用流程是服务端读取凭证，组装指令和上下文，发送请求，处理流式或完整结果，再做格式及业务校验。模型需要操作外部系统时，由程序执行工具，而不是把数据库凭证放进提示词。

生产集成还要配置超时、限流、有界重试、Token 预算和请求追踪，并为拒答、格式错误及服务不可用设置回退。浏览器前端不应直接暴露长期服务端密钥。

### 口述练习

可以直接调用 HTTP API、使用 SDK、通过框架接入，或部署本地模型服务。选择依据是复杂度、控制需求和运维能力。无论哪种方式，都需要保护凭证、控制超时成本，并对输出及工具执行做业务校验。

### 易错点

- API 兼容不代表模型行为和参数支持完全相同。
- 调用成功只表示请求完成，不表示答案正确。
- 应区分模型请求重试与业务写操作重试。

## medium-49 · 什么是查询重写？它有什么作用？如何基于 Spring AI 实现查询重写？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

查询重写把含糊、冗长或口语化的问题改成更适合检索的查询，同时保留用户意图。例如把“那个报销上限是多少”结合历史改成独立问题。Spring AI 的模块化 RAG 可使用 `RewriteQueryTransformer`，将其配置到 `RetrievalAugmentationAdvisor` 的预检索阶段，再接 `VectorStoreDocumentRetriever`。应保留原查询做对照，测改写前后召回，并防止重写改变实体或时间条件。

### 口述练习

查询重写属于检索前处理；Spring AI 可用 `RewriteQueryTransformer` 接入 RAG Advisor。

### 易错点

查询重写不是“让模型先回答”，更不能让重写结果覆盖用户的硬约束。

## medium-50 · 什么是上下文查询增强？它有什么作用？如何基于 Spring AI 实现上下文查询增强来处理无关问题？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

上下文查询增强是把检索文档作为上下文加入用户请求，使回答受证据约束。Spring AI 的 `ContextualQueryAugmenter` 可放在 RAG 生成前；默认当检索结果为空时引导模型不要凭空回答，可按业务改空上下文模板。为了处理“无关问题”，还要在检索前做领域判定、相似度阈值和元数据过滤；即使检索到片段，也应判定是否真正支持答案。

### 口述练习

Spring AI 用 `ContextualQueryAugmenter` 拼接检索证据；无关或无证据的问题应拒答或转通用问答链路。

### 易错点

“有检索结果”不代表“检索结果相关”。

## medium-51 · 什么是 Spring AI 提出的模块化 RAG 架构？预检索、检索和后检索阶段各自负责什么？

- 难度：中等
- 原始分类：3. RAG、检索与向量数据库（42 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

Spring AI 将 RAG 拆成可组合模块：预检索做查询压缩、改写、翻译和扩展；检索阶段由 DocumentRetriever 从向量库等取候选；后检索做重排、去重、压缩、融合，再由 QueryAugmenter 把证据交给生成模型。`RetrievalAugmentationAdvisor` 可组合这些组件。模块化让每段可单测、可替换，但需统一查询、文档和追踪信息。

### 口述练习

预检索改问题，检索找候选，后检索精选证据，最后增强 Prompt 生成答案。

### 易错点

不要把查询增强与查询改写混为一谈；两者发生在不同位置。

## medium-101 · 什么是工具调用 Tool Calling？如何利用 Spring AI 实现工具调用？

- 难度：中等
- 原始分类：5. LangChain、Spring AI 与框架开发（19 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

工具调用是模型输出工具名和参数，宿主程序校验并执行，再把结果回传模型。Spring AI 可把 Java 方法用 `@Tool` 声明名称/描述，通过 `ChatClient.prompt().tools(工具对象)` 提供给模型；当前版本的 `ToolCallingAdvisor` 管理“模型请求→执行→回传→继续”循环。业务侧仍需限制工具权限、参数、超时和副作用，不能因方法被注解就允许任意用户调用。

### 口述练习

Spring AI 用 `@Tool` 暴露方法，用 `ChatClient` 注册工具，框架处理调用循环，应用负责安全边界。

### 易错点

模型只提出调用，真正执行仍在 Java 应用中。

## medium-102 · 什么是结构化输出？Spring AI 是怎么实现结构化输出的？

- 难度：中等
- 原始分类：5. LangChain、Spring AI 与框架开发（19 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

结构化输出是让模型结果符合预先定义的字段和类型，便于程序处理。Spring AI 的 `ChatClient` 可用 `.call().entity(MyType.class)` 将结果映射到 Java 类型；当前文档还提供 Schema 验证/纠错和 Provider 原生结构化输出选项。仍应校验业务约束，例如金额范围、枚举和字段间一致性，处理解析失败与重试。

### 口述练习

Spring AI 用 Java 类型定义输出契约，`entity` 解析成对象；必要时启用 Schema 校验和原生约束。

### 易错点

合法 JSON 不等于业务数据正确。

## medium-103 · 什么是 Re-Reading？如何基于 Spring AI 实现 Re-Reading Advisor？

- 难度：中等
- 原始分类：5. LangChain、Spring AI 与框架开发（19 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

Re-Reading（Re2）让模型在回答前再次阅读同一问题，常见提示形式为“原问题；请再读一遍原问题”。在 Spring AI 中可实现/配置 Advisor，在请求进入模型前改写用户消息，把重读模板附加进去；官方 Advisor 文档有 ReReadingAdvisor 示例或相应能力。应在固定任务集上比较效果、Token 成本和延迟，尤其检查是否因重复问题而冲淡检索证据。

### 口述练习

Re-Reading 是输入侧的重复审题策略，Spring AI 可用 Advisor 在模型调用前插入相应模板。

### 易错点

重复一遍问题不是事实校验，也不保证推理更准。
