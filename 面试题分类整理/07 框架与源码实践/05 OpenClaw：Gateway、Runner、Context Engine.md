## easy-108 · OpenClaw 是什么？它要解决什么问题？它的核心能力有哪些？

- 难度：简单
- 原始分类：6. Agent 框架与应用开发（22 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

OpenClaw 是可自行运行的个人 AI 助手系统，把常用消息渠道、Agent 和工具连接到同一个运行环境。它要解决的是：用户能从熟悉的聊天入口发起任务，助手能持续管理会话并调用工具，而不只是返回一次文本。[OpenClaw 官方介绍](https://docs.openclaw.ai/)

其架构核心是常驻 Gateway，负责消息渠道连接和控制接口；不同客户端及设备节点连接 Gateway，渠道将用户消息送入 Agent 运行链路。[OpenClaw Gateway 架构](https://docs.openclaw.ai/concepts/architecture)

常见能力包括模型接入、工具和插件扩展、Skills、会话与记忆、消息路由及任务自动化；具体可用能力依赖配置、模型和插件。自托管使工作空间和权限更可控，但调用云模型时，发送给模型的数据仍可能离开本机。

落地时要明确哪些用户能发起任务、工具能访问哪些目录或系统，以及写操作如何审批。OpenClaw 提供运行平台，实际任务效果仍由模型能力、工具实现、上下文和权限设计共同决定。

### 口述练习

OpenClaw 是能自运行的个人 Agent 助手系统，通过 Gateway 连接消息渠道、模型、工具和设备，让用户从聊天入口发起多步任务。它的价值在于运行与集成能力，实际效果和边界仍依赖模型、工具及配置。

### 易错点

- OpenClaw 不是新的基础模型。
- 自托管运行不等于所有模型推理都在本地。
- 能接入多个用户，不等于权限和记忆天然隔离。

## easy-109 · 最近 OpenClaw 这么火，你知道它的原理吗？

- 难度：简单
- 原始分类：6. Agent 框架与应用开发（22 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、Agent 开发、AI 应用开发

### 核心回答

可以从“渠道入口—Gateway—会话—Agent 循环—工具—回复”解释其原理，不必对流行程度作无法核实的排名判断。消息进入后，系统确定对应 Agent 和会话，准备工作空间、历史、Skills 与上下文，再开始模型调用。

官方 Agent Loop 文档描述了会话内串行的运行链路，包括上下文组装、推理、工具执行、流式事件和持久化；Gateway 返回运行标识，客户端可以观察生命周期和结果。[OpenClaw Agent Loop](https://docs.openclaw.ai/concepts/agent-loop)

模型可以直接回答，也可以提出工具调用。运行时执行被允许的工具，将结果反馈给模型，再继续推进任务。过程中的历史、工具返回及任务状态为下一步提供证据；最终内容经渠道适配后交付给用户。

其工程关键是同一会话的并发控制、可用工具和权限、上下文长度、超时及终止策略。不能因为看到文本流就判断任务已完成，应核对终止状态和实际工具结果。不同版本或运行后端的内部函数可能变化，面试应重点解释职责和链路。

### 口述练习

OpenClaw 通过 Gateway 接收渠道消息，路由到会话并组装上下文，再运行模型和工具之间的循环。它管理串行会话、事件、持久化及结果交付。核心是工程运行系统，可靠性取决于权限、工具结果和停止条件。

### 易错点

- 工具结果不可信时，Agent 也可能被误导。
- 收到一次模型响应不一定代表整个任务结束。
- 内部函数和默认配置要按实际版本核对。

## medium-81 · OpenClaw 的核心组件有哪些？请描述它们之间的关系

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

可从 Gateway、Channel、会话与路由、Agent Runtime、模型 Provider、工具/Skills、插件及记忆/Context Engine 来理解。Channel 接入 Telegram 等消息，Gateway 统一接收、鉴权、路由并管理会话；Agent Runtime 组装上下文、调用模型与工具形成循环，回复再经 Gateway/Channel 发出。插件扩展渠道、工具和钩子，Context Engine 决定会话内容如何注入。具体组件名称以所用版本文档为准。

### 口述练习

Gateway 管入口和路由，Channel 管渠道，Agent Runtime 管执行，工具/插件扩展能力，Context Engine 管上下文。

### 易错点

Gateway 不是大模型本身；渠道权限与 Agent 工具权限也是两套边界。

## medium-82 · LLM 的 Context Window 有上限，长对话时如何保证 Agent 仍然能正常工作？OpenClaw 是怎么做的？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

通用做法是预算管理、保留最近轮次与任务关键状态、裁剪旧工具结果、将早期对话压缩成摘要，并把长期事实外置检索。OpenClaw 文档区分 session pruning（主要缩减旧工具结果）与 compaction（将早期会话概括为摘要，保留近期消息）；上下文接近上限或溢出时可触发压缩恢复。完整历史仍保存在会话记录中，压缩改变的是下一次模型看到的内容。

### 口述练习

OpenClaw 用工具结果修剪和会话压缩控制窗口，必要时靠外部记忆召回关键事实。

### 易错点

修剪和压缩不是同一件事；压缩摘要可能遗漏约束，需可回查原记录。

## medium-83 · Agent 调用工具可能返回超大结果（比如代码搜索返回 50KB），这会带来什么问题？你会怎么处理？OpenClaw 是怎么做的？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

大结果会占据上下文，推高延迟和费用，还可能把关键指令挤出窗口。工程上限制工具输出大小，分页、按相关性过滤、摘要或只返回文件引用；需要细节时再定向读取。OpenClaw 的 session pruning 可对旧工具结果做投影式修剪，不改写原始会话记录；compaction 进一步总结旧对话。当前轮关键工具结果不应盲截断，否则会破坏执行判断。

### 口述练习

先在工具层限量并支持分页，再修剪旧结果；OpenClaw 的 pruning 重点就是避免工具输出撑爆上下文。

### 易错点

不能直接丢弃错误码、关键行或引用位置。

## medium-84 · 当对话历史实在太长、裁剪也不够用时，还有什么办法？什么是 Compaction？OpenClaw 的 Compaction 策略是怎样的？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

Compaction 是把较早轮次摘要成短的会话条目，保留最近消息，使后续请求落在窗口内。OpenClaw 默认自动压缩：临近上限或模型报溢出时触发，摘要存入会话记录；选择分界点时保持工具调用与结果成对，避免截断半个动作。它保留完整原始历史供回查；用户也可主动触发。压缩后应保留任务目标、关键决策、未完成事项和不可变约束。

### 口述练习

裁剪只减旧工具结果，Compaction 则把早期对话摘要入会话，留下近期原文。

### 易错点

不要把摘要当无损存储；重要事实应有独立持久化。

## medium-85 · OpenClaw 把 Context 管理抽象成了可插拔的 Context Engine，为什么要做这层抽象？这个设计能支持哪些不同的策略？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

不同 Agent 对上下文组装、长期记忆和压缩的需求不同，抽象层让运行时不绑定单一算法。OpenClaw 的 Context Engine 可负责消息摄入、每轮上下文组装、压缩与轮后处理；内置 legacy 策略以近期消息和摘要为主，插件可实现层级摘要、按主题检索、跨会话记忆或更精细的 Token 分配。插件若接管压缩，必须正确处理溢出与会话一致性。

### 口述练习

可插拔 Context Engine 让不同项目替换上下文和压缩策略，而不用改 Agent 主循环。

### 易错点

插件声明“不接管压缩”也不意味着无需实现相应委托逻辑。

## medium-90 · 不同的 LLM Provider 对 Tool Schema 的支持不完全一致，你会怎么处理这种差异？OpenClaw 是怎么做 Schema 适配的？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发

### 核心回答

内部使用规范化工具定义，再按 Provider 能力转换为各自支持的 Schema 子集：处理类型、枚举、可选字段、严格模式、并行调用等差异。发送前校验并记录降级，模型返回后再次验证参数，复杂结构可改为扁平字段或字符串化 JSON。OpenClaw 的模型/Provider 适配层也需处理工具描述与调用格式的兼容；具体转换细节随版本变化，面试应以当前代码/文档为准，不能假定所有 Provider 都完整支持 JSON Schema。

### 口述练习

先定义内部工具契约，再针对 Provider 做 Schema 转换和结果校验；无法支持的特性明确降级。

### 易错点

模型返回“符合 Schema”不等于已通过应用侧校验或权限检查。

## medium-94 · 多 Agent 之间如何通信和协调？OpenClaw 的 Gateway 在其中扮演什么角色？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

多 Agent 需要任务 ID、消息/产物格式、状态机、超时、重试和归属者。OpenClaw Gateway 负责会话与路由、接入渠道、跨 Agent 消息的策略检查和交付；子 Agent 有自己的会话，完成后向请求方反馈。共享任务状态应存持久层，消息送达不等于业务完成；需避免循环委托和越权读取其他会话。

### 口述练习

Gateway 是协作的入口与控制面，帮助路由和交付；真正业务状态仍应由任务/会话记录管理。

### 易错点

不能因为 Agent 都在同一 Gateway 上，就默认允许互读对话或跨渠道发消息。

## medium-96 · OpenClaw 的 Gateway 对 Agent 请求做了幂等性处理。为什么 Agent 系统特别需要幂等性？工具已经产生副作用时怎么办？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

Agent 可能因网络重试、超时恢复或模型重复规划而多次发起同一动作。OpenClaw 的 Hook Agent 请求支持幂等键，在同一请求身份与路由条件下重放既有运行结果，避免重复入队；但这不自动撤销外部工具副作用。写操作要把幂等键传到下游 API，采用事务、去重表或业务唯一约束；若副作用已发生，查询状态并走补偿/人工处理，不盲目重试。

### 口述练习

入口幂等避免重复启动，工具幂等避免重复扣款/发信；副作用已发生时先查状态再补偿。

### 易错点

“请求幂等”不等于“整条 Agent 工作流所有工具都幂等”。

## hard-20 · 在 OpenClaw 中，一条用户消息从进入系统到收到回复，完整链路是怎样的？

- 难度：困难
- 原始分类：2. Agent、推理与框架（16 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

按官方消息链路：Channel 收到并规范化入站事件，Gateway 先做渠道准入与 Agent binding 路由，形成会话键；随后去重、短时合并/防抖，并在已有会话运行时排队。Agent Runtime 读取会话状态、组装上下文与可用工具，调用模型；如产生工具调用，按策略执行并把结果回传，循环直到终止。运行中可流式输出，结束后持久化消息/状态；Gateway 再按渠道限制分块、格式化并发送回复。失败、超时、权限拒绝与重复消息都有单独处理路径。

### 口述练习

消息经过渠道接入、路由定会话、去重排队、Agent 模型/工具循环、持久化，再由渠道发送答复。

### 易错点

Binding 只选 Agent，不等于渠道准入或工具授权；同一会话通常要串行处理，避免状态竞争。

## hard-21 · OpenClaw 的 Agent Runner 是如何工作的？一次 Agent 运行经历了哪些阶段？

- 难度：困难
- 原始分类：2. Agent、推理与框架（16 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

从运行视角可分为接收请求与会话锁定、上下文装配、模型推理、解析工具调用、工具权限/沙箱检查与执行、结果回注、重复循环、最终回复及持久化。运行时要处理流式事件、取消、限时、上下文压缩和模型错误恢复；每次工具调用与结果保持配对，避免会话重放时状态不一致。具体类名和内部阶段随版本变化，回答应以官方 Agent Loop 文档与目标版本源码为准。

### 口述练习

Agent Runner 是有会话边界的执行循环：组装上下文→模型决策→工具观察→继续或结束，并同步记录与流式回传。

### 易错点

不要把一次模型 API 调用等同于一次完整 Agent 运行；一次运行可能包含多轮工具调用。
