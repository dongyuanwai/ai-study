## easy-63 · 子 Agent（Subagent）模式有什么优势和挑战？父 Agent 调用子 Agent 时需要考虑哪些边界问题？

- 难度：简单
- 原始分类：4. AI Agent 原理与设计（25 题）
- 资料类型：原始面试题
- 标签：AI、大模型、Agent

### 核心回答

子 Agent 模式把可独立处理的子任务委派给专门执行单元。优势包括并行提速、专业分工和上下文隔离，例如分别分析接口、数据库和测试，再由父 Agent 汇总。

挑战是沟通与整合成本、结论冲突、重复工作和费用放大。若多个子 Agent 修改同一文件，还可能发生覆盖；每个 Agent 的单项成功也不保证整体目标完成。

委派应明确输入、目标、验收标准、允许工具、数据范围、预算、截止时间和输出格式。子 Agent 返回结果时提供证据、修改位置和未解决问题，父 Agent 负责核验与整合。写任务最好分配互不重叠的范围；权限按最小需求下发，敏感上下文不应全量复制。父任务取消或预算耗尽时，应能取消子任务并回收资源。

例如，代码评审可以让子 Agent 独立查安全和性能问题，但最终报告必须由父 Agent 去重、复现并判断严重程度。对于强依赖的短流程，拆分反而可能比单 Agent 更慢。

### 口述练习

子 Agent 适合独立且可验收的任务，能并行并减少主上下文负担。调用时要明确权限、数据、预算、产出和取消边界，父 Agent 负责整合与验证。协作成本和共享写冲突是我会优先控制的风险。

### 易错点

- 更多 Agent 不必然带来更高准确率或更低延迟。
- 子 Agent 的结论不能直接当成事实，也不能默认继承全部权限。

## easy-87 · 多 Agent 协作有哪些常见的编排模式？各自适合什么场景？

- 难度：简单
- 原始分类：5. MCP、A2A 与多智能体协议（19 题）
- 资料类型：原始面试题
- 标签：AI、大模型、Agent

### 核心回答

常见编排模式可以按任务依赖和控制方式选择：

| 模式 | 适用场景与取舍 |
| --- | --- |
| 串行流水线 | 处理顺序固定，如抽取、审核、生成；容易控制，但前序错误会传递。 |
| 并行分支 / DAG | 可拆分的检索或分析；降低等待时间，需合并冲突和限制总成本。 |
| Supervisor 调度 | 主 Agent 分配任务给专家；灵活，但协调者可能成为瓶颈。 |
| Handoff 接力 | 当前 Agent 将处理职责转交更合适的 Agent；需明确状态和用户交互归属。 |
| 讨论与评审 | 方案比较、审查和反驳；能增加检查角度，但也可能共同犯错。 |
| 共享工作区 | 多 Agent 读取或更新任务板、文件和状态；需处理一致性、并发及来源。 |

例如客服路由适合主管或接力，调研任务适合并行，固定报表流程适合 DAG。设计时应先明确输入输出契约、谁有最终决定权、如何停止和如何验收，再决定是否需要动态 Agent。

### 口述练习

我会根据任务依赖选模式：固定流程用流水线或 DAG，可独立工作用并行，有专家分工用主管或接力，关键方案增加评审。多 Agent 的价值来自有效分工，必须明确结果契约、状态所有权、预算和终止条件。

### 易错点

- 多个 Agent 使用同一模型讨论，不代表形成独立可靠证据。
- 单机内部编排不一定需要网络协议。
