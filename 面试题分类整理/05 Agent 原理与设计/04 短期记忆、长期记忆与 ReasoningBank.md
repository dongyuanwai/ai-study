## easy-59 · AI Agent 的记忆机制有哪些类型？短期记忆和长期记忆分别怎么实现？

- 难度：简单
- 原始分类：4. AI Agent 原理与设计（25 题）
- 资料类型：原始面试题
- 标签：AI、大模型、Agent

### 核心回答

Agent 记忆可以按保存时间区分短期和长期，也可以按内容区分事实、经历和操作经验。不同划分解决不同问题，不能混成一个无差别的历史库。

短期记忆服务于当前会话或任务，包括消息、计划、工具结果和进度。可以保存在运行状态、缓存或检查点中，并通过滑动窗口、摘要和按需回查控制上下文大小。长期记忆跨会话保存稳定偏好、已验证事实或有效经验，通常使用数据库、文档存储以及向量或关键词检索。

例如，本次订单查询的物流结果属于短期状态；用户明确确认的报告格式偏好可以进入长期记忆。长期记忆应记录主体、来源、时间、可信度和失效条件，并提供更正与删除机制。使用前需要根据当前任务筛选，不能将所有历史都拼进提示词。敏感信息应减少保存，并严格区分不同用户和租户。

### 口述练习

短期记忆保存当前任务状态，长期记忆保存跨会话有价值的信息。前者重在上下文与恢复，后者重在筛选、检索和治理。我会只存值得复用且有来源的信息，并维护有效期、权限和删除能力。

### 易错点

- 把历史消息写进数据库不等于已具备高质量长期记忆。
- 模型参数中的知识与应用保存的用户记忆是不同机制。

## easy-60 · 如何让 AI Agent 具备长期记忆能力？有哪些存储和检索方案？

- 难度：简单
- 原始分类：4. AI Agent 原理与设计（25 题）
- 资料类型：原始面试题
- 标签：AI、大模型、Agent

### 核心回答

长期记忆需要“提取、判断、存储、检索、更新、删除”的完整流程。先从对话和执行结果中识别值得复用的信息，再判断是否可信、是否获准保存以及适用范围，避免把临时猜测直接写成事实。

结构化偏好和用户设置适合关系数据库或键值存储；自由文本经验适合文档存储；语义相近的经历可以通过向量检索，精确名称、日期和业务编号则适合关键词及字段过滤。实践中常用混合检索，再按相关性、时间、可信度和来源重排。

例如，用户确认“周报采用本周成果、风险、下周计划三段”后，保存偏好及来源；生成下次周报时按用户 ID 和任务类型检索。如果用户修改格式，应更新或废弃旧记录，而不是同时返回矛盾规则。记忆注入上下文时标明它是历史资料；重要业务事实仍需实时核实。评测要检查命中率、过期记忆误用、跨用户泄漏和删除是否生效。

### 口述练习

我会先建立可治理的记忆生命周期，再选择存储。结构化信息进数据库，经验文本用关键词与向量混合检索，并加用户隔离、来源、时间和失效条件。检索到的记忆只是参考，不能绕过当前权限或实时核验。

### 易错点

- 向量相似度高不代表记忆仍然有效或可信。
- 长期记忆需要去重、冲突处理和删除，不能只做无限追加。

## medium-73 · 在大模型应用中，通常如何实现长短期记忆机制？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、大模型

### 核心回答

短期记忆保存当前会话的最近消息、任务状态与工具结果，用会话存储和上下文窗口承载；长期记忆保存跨会话稳定事实、偏好或知识，可用关系库/文档库加检索索引，按用户、时间和权限召回。旧对话可摘要为长期候选，但写入前要去噪、征得授权或遵守隐私策略；读取时标注来源与新鲜度，支持更正和删除。

### 口述练习

短期记忆维护当前任务连续性，长期记忆跨会话检索稳定信息；两者都要有权限与过期机制。

### 易错点

把全部历史原样塞进 Prompt 不是可持续的记忆设计。

## medium-79 · 如何实现 AI 多轮对话功能？如何解决对话记忆持久化问题？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：后端、编程导航

### 核心回答

以租户、用户和会话 ID 标识对话，按顺序持久化用户消息、模型回复、工具调用和状态；每轮组装最近消息、必要摘要及相关长期记忆，控制 Token 预算。数据库保存原始记录，摘要与检索索引作为派生数据，可重建。并发请求用版本号或锁防止顺序错乱；加入权限、加密、保留期限和删除接口。

### 口述练习

会话数据库保真，模型上下文只放近期、摘要和相关记忆；持久化还要解决顺序、并发和隐私。

### 易错点

不要把服务进程内存当长期存储，也不要让不同用户共享会话键。

## medium-80 · （OpenClaw前置知识）解释「短期记忆」和「长期记忆」在 Agent 系统中的区别，分别适合怎么存储和检索？

- 难度：中等
- 原始分类：4. Agent、协议与 OpenClaw（28 题）
- 资料类型：原始面试题
- 标签：AI、OpenClaw、大模型应用开发、AI应用开发、Agent开发

### 核心回答

短期记忆指当前会话中为完成任务必需的近期消息、计划和工具状态，可保存在会话日志/检查点，并在每轮按预算装入上下文。长期记忆是跨会话可复用的偏好、事实和知识，存储在持久数据库或文件，并通过关键词/向量检索按需读取。重要的是写入门槛、来源、更新时间、权限与更正删除，而不是单纯“存得越多越好”。

### 口述练习

短期记忆服务当前任务，长期记忆跨会话复用；前者直接组装，后者按需检索。

### 易错点

摘要不一定准确，长期写入前应校验稳定性和授权。

## hard-13 · 如何让 LLM Agent 具备长期记忆能力？

- 难度：困难
- 原始分类：2. Agent、推理与框架（16 题）
- 资料类型：原始面试题
- 标签：大模型、AI、Agent

### 核心回答

长期记忆不能等同于无限聊天记录。设计写入流水线：从对话提取候选事实/偏好/任务成果→确认用户授权和稳定性→去重、加来源、时间与置信度→写关系库/文档库，必要时生成向量索引。读取时按用户、租户、任务、时间和权限过滤，混合关键词与语义检索，给模型少量高相关记录并标注“可能过期”。支持更正、删除、TTL 和冲突解决；把即时会话状态留在短期检查点。评测记忆命中、错误召回、隐私泄漏和陈旧信息影响。

### 口述练习

长期记忆要有受控写入和按需检索，并能更正、过期和删除；不是把旧对话全部塞进上下文。

### 易错点

模型从一次闲聊提取的“偏好”不一定是真实且永久的事实。

## concept-reasoningbank · ReasoningBank 与保存完整对话日志有什么不同？

- 难度：中等
- 原始分类：新概念研读
- 资料类型：补充研读
- 标签：ReasoningBank、推理记忆、经验提炼、MaTTS
- 来源：[ReasoningBank: Scaling Agent Self-Evolving with Reasoning Memory](https://arxiv.org/abs/2509.25140)
- 来源日期：2025-09-29；核对日期：2026-11-08

### 核心回答

ReasoningBank 从成功和失败的任务轨迹中提取可迁移的策略，而不是只存原始操作记录。执行新任务时检索相关记忆，结束后再把经验写回。

MaTTS 通过增加任务交互的计算量获得多样经验，利用记忆与推理时扩展相互促进。

### 口述练习

日志保存发生了什么，ReasoningBank 更关心以后遇到相似问题应该怎样做，也会保留失败带来的教训。

### 易错点

- 外部经验记忆不等于修改模型权重。
- 模型对成功或失败的判断可能有噪声。
- 论文中的基准结果不能保证所有任务都提升。

## concept-agent-memory · 为什么 Agent 记忆系统不能只设计写入和检索？

- 难度：中等
- 原始分类：新概念研读
- 资料类型：补充研读
- 标签：Agent Memory、记忆维护、记忆检索、遗忘与评估
- 来源：[Learning to Remember: Advances in Memory Mechanisms for Large Language Models](https://arxiv.org/abs/2610.35089)
- 来源日期：2026-10-26；核对日期：2026-11-08

### 核心回答

记忆会过期、冲突或变得无关，因此还要考虑维护、整合、遗忘和评估。该综述从外部存储、参数相关机制与支持智能体演进的记忆等角度组织研究。

设计时需要区分记忆保存在哪里、何时更新，以及是否真正帮助后续任务。

### 口述练习

能记住不等于会正确使用；完整系统还需要更新旧记忆、处理冲突，并检查记忆对任务的影响。

### 易错点

- 外部数据库中的记忆不等同于模型参数。
- 评估是横跨各类记忆机制的环节。
- 综述整理已有研究，不代表全部分类都是新发明。
